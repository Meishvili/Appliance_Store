# Appliance_Store
## პროექტის აღწერა
Appliance store არის საყოფაცხოვრებო ტექნიკის ონლაინ მაღაზიის ვებ-სისტემა. ის წყვეტს პრობლემას, როდესაც მყიდველს უჭირს სხვადასხვა მოდელის შედარება და შეკვეთის გაფორმება ფილიალში, მაღაზიას კი შეკვეთის და მარაგის მართვა ხელით უწევს. სისტემა განკუთვნილია მყიდველებისთვის, მაღაზიის ადმინისტრაციისთვის და მენეჯერისთვის. მყიდველს შეუძლია კატალოგში ძებნა, კალათაში დამატება და შეკვეთის გაფორმება, ადმინისტრატორი მართავს პროდუქტებს და შეკვეთებს, ხოლო მენეჯერი ხედავს გაყიდვების ანგარიშებს.

## Acceptance Criteria: Given/When/Then

Given: საწყისი მდგომარეობა
When: მოქმედება
Then: მოსალოდნელი შედეგი

## User Story

Story 1. რეგისტრაცია და ავტორიზაცია
მყიდველს სურს შექმნას ანგარიში და შევიდეს სისტემაში, რათა გააფორმოს შეკვეთა და ნახოს თავისი მონაცემები.

Given მომხმარებელი არ არის დარეგისტრირებული, When ის შეავსებს ელ-ფოსტასა და პაროლს (მინ. 8 სიმბოლო) და დააჭერს "რეგისტრაციას", Then სისტემა შექმნის ანგარიშს და შეიყვანს სისტემაში.
Given ელ-ფოსტა უკვე დარეგისტრირებულია, When მომხმარებელი სცდილობს იმავე ელ-ფოსტით რეგისტრაციას, Then სისტემა აჩვენებს შეტყობინებას და ახალ ანგარიშს არ შექმნის.

Story 2. კატალოგის ნახვა კატეგორიებით
მყიდველს სურს დაათვალიეროს ტექნიკის სია კატეგორიების მიხედვით, რათა სწრაფად მიაგნოს სასურველ პროდუქტს.

Given კატალოგში არის პროდუქტები სხვადასხვა კატეგორიაში, When მყიდველი აირჩევს კატეგორიას "მაცივრები", Then სისტემა აჩვენებს მხოლოდ ამ კატეგორიის პროდუქტებს.
Given არჩეულ კატეგორიაში პროდუქტი არ არის, When მყიდველი გახსნის ამ კატეგორიას, Then სისტემა აჩვენებს შეტყობინებას "პროდუქტები ვერ მოიძებნა".

Story 3. პროდუქტის გვერდი
მყიდველს სურს ნახოს პროდუქტის მონაცემები დეტალურად, რათა გადაწყვიტოს შეესაბამება თუ არა მის საჭიროებას.

Given პროდუქტი არსებობს კატალოგში, When მყიდველი დააჭერს მის ბარათს, Then გაიხსნება გვერდი სახელით, ფასით, ფოტოთი და მახასიათებლებით.
Given პროდუქტი მარაგში აღარ არის, When მყიდველი გახსნის მის გვერდს, Then სისტემა აჩვენებს სტატუსს "მარაგში არ არის" და კალათაში დამატების ღილაკი გაითიშება.

Story 4. ძებნა და ფილტრი
მყიდველს სურს გაფილტროს პროდუქტი სახელით, ბრენდით და ფასის მიხედვით, რათა სწრაფად იპოვოს თავისი ბიუჯეტის შესაფერი მოდელი. 

Given კატალოგში არის რამდენიმე ბრენდი, When მყიდველი აირჩევს ბრენდს და ფასის დიაპაზონს 300–800 ლარი, Then სისტემა აჩვენებს მხოლოდ იმ პროდუქტებს, რომლებიც ორივე პირობას აკმაყოფილებს.
Given ძებნის სიტყვას შედეგი არ აქვს, When მყიდველი გაუშვებს ძებნას, Then სისტემა აჩვენებს შეტყობინებას "შედეგი ვერ მოიძებნა".

Story 5. კალათა
მყიდველს სურს დაამატოს პროდუქტი კალათაში და დააზუსტოს რაოდენობა, რათა რამდენიმე ნივთი ერთად შეუკვეთოს.
Given მყიდველი ათვალიერებს პროდუქტს, რომელიც მარაგშია, When დააჭერს "კალათაში დამატებას", Then პროდუქტი გამოჩნდება კალათაში და ჯამური ფასი განახლდება.
Given პროდუქტის მარაგი 3 ცალია, When მყიდველი რაოდენობას 4-ზე გაზრდის, Then სისტემა აჩვენებს შეტყობინებას და რაოდენობას დატოვებს 3-ზე.

Story 6. შეკვეთის გაფორმება
მყიდველს სურს გააფორმოს შეკვეთა კალათაში მოთავსებულ პროდუქტებზე.

Given კალათაში არის მინიმუმ 1 პროდუქტი და მყიდველი ავტორიზებულია, When ის შეავსებს მისამართს და დააჭერს "შეკვეთის დადასტურებას", Then სისტემა შექმნის შეკვეთას სტატუსით "მიღებულია" და აჩვენებს შეკვეთის ნომერს.
Given კალათა ცარიელია, When მყიდველი სცდილობს შეკვეთის გაფორმებას, Then სისტემა აჩვენებს შეტყობინებას და შეკვეთას არ შექმნის.

Story 7. ნაღდი ანგარიშსწორება მიტანისას
მყიდველს სურს ნაღდი ფულით გადახდა ტექნიკის მიღებისას, რათა წინასწარ ონლაინ არ მოუწიოს ბარათის მონაცემების შეყვანა.

Given მყიდველი ავსებს შეკვეთას, When ის გადახდის მეთოდად აირჩევს "ნაღდი ანგარიშსწორება", Then შეკვეთა შეიქმნება გადახდის სტატუსით "გადასახდელია".
Given მყიდველმა გადახდის მეთოდი არ აირჩია, When ის დააჭერს დადასტურებას, Then სისტემა მოითხოვს მეთოდის არჩევას და შეკვეთას არ შექმნის.

Story 8. ბარათით ონლაინ გადახდა
მყიდველს სურს ბარათით, ონლაინ გადახდა.

Given მყიდველმა შეკვეთა გააფორმა და გადახდის მეთოდად აირჩია "ბარათით გადახდა", When ის გადახდის გვერდზე შეიყვანს ვალიდურ ბარათის მონაცემებს და დაადასტურებს, Then გადახდა წარმატებით სრულდება, შეკვეთას ენიჭება გადახდის სტატუსი "გადახდილია" და მყიდველი ხედავს დადასტურებას.
Given ბარათზე არასაკმარისი თანხაა ან მონაცემები არასწორია, When მყიდველი სცდილობს გადახდას, Then სისტემა აჩვენებს გადახდის შეცდომას, შეკვეთა რჩება სტატუსით "გადასახდელია" და მყიდველს შეუძლია ხელახლა სცადოს ან ნაღდი ანგარიშსწორება აირჩიოს.
Given გადახდის პროვაიდერი დროებით მიუწვდომელია, When მყიდველი სცდილობს გადახდას, Then სისტემა აჩვენებს შეტყობინებას და თანხას არ ჩამოწერს.

Story 9. პროდუქტის დამატება და რედაქტირება
ადმინისტრატორს სურს პროდუქტის დამატება ან შეცვლა, რათა კატალოგი ყოველთვის აქტუალური იყოს.

Given ადმინისტრატორი ავტორიზებულია, When ის შეავსებს პროდუქტის სახელს, ფასს, კატეგორიას და მარაგს და დააჭერს შენახვას, Then პროდუქტი გამოჩნდება კატალოგში.
Given ფასის ველში ჩაწერილია უარყოფითი რიცხვი, When ადმინისტრატორი სცდილობს შენახვას, Then სისტემა აჩვენებს ვალიდაციის შეცდომას და პროდუქტს არ შეინახავს.

Story 10. შეკვეთის სტატუსის მართვა
ადმინისტრატორს ესაჭიროება ნახოს შეკვეთები და შეცვალოს მათი სტატუსი, რათა მყიდველმა იცოდეს, სად არის მისი შეკვეთა.

Given სისტემაში არის შეკვეთა სტატუსით "მიღებულია", When ადმინისტრატორი შეცვლის სტატუსს "გაგზავნილზე", Then სტატუსი განახლდება და მყიდველი ახალ სტატუსს დაინახავს.
Given მომხმარებელი არ არის ადმინისტრატორი, When ის სცდილობს სტატუსის შეცვლას, Then სისტემა წვდომას უარყოფს.

Story 11. შეკვეთების ისტორია
მყიდველს სურს ნახოს თავისი წინა შეკვეთების სია და მათი სტატუსები.

Given მყიდველი ავტორიზებულია და აქვს მინიმუმ 1 გაფორმებული შეკვეთა, When ის გახსნის "ჩემი შეკვეთები" გვერდს, Then სისტემა აჩვენებს მხოლოდ მისი შეკვეთების სიას თარიღით, ჯამური თანხითა და სტატუსით, ახლიდან ძველისკენ.
Given მყიდველს შეკვეთა არ აქვს გაფორმებული, When ის გახსნის "ჩემი შეკვეთები" გვერდს, Then სისტემა აჩვენებს შეტყობინებას "შეკვეთები ჯერ არ გაქვთ".
Given მყიდველი ავტორიზებული არ არის, When ის სცდილობს "ჩემი შეკვეთების" გახსნას, Then სისტემა გადაიყვანს შესვლის გვერდზე.

Story 12. გაყიდვების ანგარიში
მაღაზიის მფლობელს/მენეჯერს სურს ნახოს გაყიდვების ანგარიში არჩეული პერიოდის მიხედვით, რათა გაიგოს რომელი პროდუქტი იყიდება უკეთ და სწორად დაგეგმოს მარაგი.

Given მენეჯერი ავტორიზებულია და არჩეულ პერიოდში არის დადასტურებული შეკვეთები, When ის აირჩევს პერიოდს (მაგ. ბოლო 30 დღე) და გახსნის ანგარიშს, Then სისტემა აჩვენებს შეკვეთების რაოდენობას, ჯამურ შემოსავალს და ყველაზე ხშირად გაყიდულ პროდუქტებს.
Given არჩეულ პერიოდში შეკვეთა არ არის, When მენეჯერი გახსნის ანგარიშს, Then სისტემა აჩვენებს შეტყობინებას "ამ პერიოდში გაყიდვები არ არის" და ნულოვან მაჩვენებლებს.
Given მომხმარებელი არ არის მენეჯერი ან ადმინისტრატორი, When ის სცდილობს ანგარიშის გახსნას, Then სისტემა წვდომას უარყოფს.

Story 13. პროდუქტების შედარება
